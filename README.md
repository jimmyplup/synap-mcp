# Synap MCP Server

The MCP (Model Context Protocol) server behind **`com.linkrra/synap`** in the
[official MCP registry](https://registry.modelcontextprotocol.io) — this repository
is the reviewable source of the exact router deployed at the live endpoint:

```
https://pool.linkrra.com/mcp     (streamable HTTP, JSON-RPC 2.0, spec 2025-06-18)
```

[Synap](https://synap.linkrra.com) is Linkrra's OpenAI-compatible inference API for
open models served on Linkrra's own GPUs.

## Tools

| Tool | Cost | Auth |
|---|---|---|
| `synap_list_models` | free | none |
| `synap_get_model` | free | none |
| `synap_estimate_cost` | free | none |
| `synap_chat_completion` | billed per token at the public `/v1/models` price | `Authorization: Bearer <Synap API key>` |

Auth is pass-through only: the caller's API key travels in the standard
`Authorization: Bearer` header on the POST to `/mcp`, exactly as it would on a
direct call to `/v1/chat/completions`. **No key is read, stored or generated by
this server** — see `routes.js`, which forwards the header untouched. With no
key, the paid tool returns an error and nothing is spent; the three read-only
tools need no key at all.

## Design

A single hand-rolled Express router (`routes.js`, ~360 lines) speaking MCP's
Streamable HTTP transport with no `@modelcontextprotocol/sdk` dependency — the
transport this server needs (one request in, one JSON response out) is a thin
layer over Express, and the whole surface is small enough to read in one sitting.
Supported protocol revisions: `2025-06-18`, `2025-03-26`, `2024-11-05`.

## Run standalone

```bash
npm install && npm start     # serves :8080/mcp
```

## Try the live endpoint

```bash
curl -s https://pool.linkrra.com/mcp -X POST \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

Get an API key at [synap.linkrra.com](https://synap.linkrra.com).
